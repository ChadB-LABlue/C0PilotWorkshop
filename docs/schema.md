# Task Manager CLI Technical Design

## 1. Data models

### Task
- `id`
  - Type: `string`
  - Required: Yes
  - Validation: must be a non-empty trimmed string; generated by service (not user-supplied on create); unique within in-memory store; immutable after creation.
- `title`
  - Type: `string`
  - Required: Yes
  - Validation: must be a string; trim leading/trailing whitespace before persistence; trimmed length must be `1..120`.
- `description`
  - Type: `string`
  - Required: Yes
  - Validation: must be a string; length must be `0..1000`; empty string allowed.
- `status`
  - Type: `'todo' | 'in-progress' | 'done'`
  - Required: Yes
  - Validation: must be exactly one of `'todo'`, `'in-progress'`, `'done'`; default is `'todo'` on create.
- `priority`
  - Type: `'low' | 'medium' | 'high'`
  - Required: Yes
  - Validation: must be exactly one of `'low'`, `'medium'`, `'high'`; default is `'medium'` on create.
- `createdAt`
  - Type: `string` (ISO-8601 timestamp)
  - Required: Yes
  - Validation: system-generated with `new Date().toISOString()`; must parse to a valid date; immutable afterward.
- `updatedAt`
  - Type: `string` (ISO-8601 timestamp)
  - Required: Yes
  - Validation: system-generated with `new Date().toISOString()`; must parse to a valid date; set at create time and refreshed on every successful update; must be greater than or equal to `createdAt`.

### TaskStore
- `tasks`
  - Type: `Task[]`
  - Required: Yes
  - Validation: in-memory array only; initialized empty at process start.

### ListQuery
- `status`
  - Type: `'todo' | 'in-progress' | 'done' | undefined`
  - Required: No
  - Validation: when provided, must be an allowed status.
- `priority`
  - Type: `'low' | 'medium' | 'high' | undefined`
  - Required: No
  - Validation: when provided, must be an allowed priority.
- `sort`
  - Type: `'priority' | 'createdAt' | undefined`
  - Required: No
  - Validation: when provided, must be an allowed sort key.
- `desc`
  - Type: `boolean`
  - Required: No
  - Validation: may be true only when `sort` is provided.

## 2. File structure

```text
src/
  index.js                     # CLI entry point; parses argv, dispatches command, sets exit code.
  constants/
    enums.js                   # Allowed status/priority values and priority ranking map.
  core/
    task-store.js              # In-memory task collection and low-level CRUD accessors.
    task-service.js            # Business logic: create/update/delete/list with validation and timestamps.
  commands/
    create-task.js             # Handles create command input/output contract.
    list-tasks.js              # Handles list command with filter and sort options.
    update-task.js             # Handles update command and partial field updates.
    delete-task.js             # Handles delete command by id.
  utils/
    parse-args.js              # Minimal command/flag parser around process.argv.
    validators.js              # Input validation helpers for id/title/description/enums/sort options.
    format-output.js           # Consistent stdout rendering for task rows and empty state.
test/
  task-service.create.test.js  # Tests create behavior only.
  task-service.list.test.js    # Tests list/filter/sort behavior only.
  task-service.update.test.js  # Tests update behavior only.
  task-service.delete.test.js  # Tests delete behavior only.
```

## 3. Module responsibilities

### `src/index.js`
- Exports: none (entry file).
- Responsibilities:
  - Parse CLI arguments via `parse-args.js`.
  - Route to one command module.
  - Handle top-level `try/catch` and map outcomes to exit codes.
- Dependencies:
  - `src/commands/*.js`
  - `src/utils/parse-args.js`
  - `src/utils/format-output.js`

### `src/constants/enums.js`
- Exports:
  - `TASK_STATUS`
  - `TASK_PRIORITY`
  - `PRIORITY_ORDER`
- Responsibilities:
  - Centralize allowed enum values and sort ranking.
- Dependencies: none.

### `src/core/task-store.js`
- Exports:
  - `createTaskStore()`
- Responsibilities:
  - Own in-memory `tasks` array.
  - Provide low-level methods (`add`, `getAll`, `findById`, `updateById`, `removeById`).
- Dependencies: none.

### `src/core/task-service.js`
- Exports:
  - `createTaskService(taskStore)`
- Responsibilities:
  - Enforce validation rules and defaults.
  - Create IDs/timestamps.
  - Implement filtering by status/priority and sorting by priority/creation date.
  - Return success/failure result objects consumed by commands.
- Dependencies:
  - `src/constants/enums.js`
  - `src/utils/validators.js`
  - `src/core/task-store.js`

### `src/commands/create-task.js`
- Exports:
  - `runCreateTask(args, taskService)`
- Responsibilities:
  - Translate parsed flags to service call.
  - Return command result for `index.js` to print.
- Dependencies:
  - `src/core/task-service.js`

### `src/commands/list-tasks.js`
- Exports:
  - `runListTasks(args, taskService)`
- Responsibilities:
  - Build `ListQuery` from flags.
  - Request filtered/sorted tasks from service.
- Dependencies:
  - `src/core/task-service.js`

### `src/commands/update-task.js`
- Exports:
  - `runUpdateTask(args, taskService)`
- Responsibilities:
  - Validate required `id` presence at command boundary.
  - Forward partial updates to service.
- Dependencies:
  - `src/core/task-service.js`

### `src/commands/delete-task.js`
- Exports:
  - `runDeleteTask(args, taskService)`
- Responsibilities:
  - Validate required `id` presence and call delete.
- Dependencies:
  - `src/core/task-service.js`

### `src/utils/parse-args.js`
- Exports:
  - `parseArgv(argv)`
- Responsibilities:
  - Convert raw argv to `{ command, options }`.
- Dependencies: none.

### `src/utils/validators.js`
- Exports:
  - `validateTitle(title)`
  - `validateDescription(description)`
  - `validateStatus(status)`
  - `validatePriority(priority)`
  - `validateId(id)`
  - `validateSort(sort, desc)`
- Responsibilities:
  - Provide reusable validation checks and descriptive `Error` throws.
- Dependencies:
  - `src/constants/enums.js`

### `src/utils/format-output.js`
- Exports:
  - `formatTask(task)`
  - `formatTaskList(tasks)`
  - `formatError(message)`
- Responsibilities:
  - Keep user-facing output consistent and readable.
- Dependencies: none.

### `test/*.test.js`
- Exports: none.
- Responsibilities:
  - Validate one behavior per test function using Node `assert`.
- Dependencies:
  - `node:assert`
  - `src/core/task-service.js`
  - `src/core/task-store.js`

## 4. Error handling strategy

- `ValidationError`
  - Thrown by: `src/utils/validators.js` and service-level guard clauses in `src/core/task-service.js`.
  - Used for: invalid title/description/status/priority/id/sort input.

- `NotFoundError`
  - Thrown by: `src/core/task-service.js` when update/delete targets a non-existent task id.
  - Used for: unknown task id in mutation commands.

- `Error` (generic runtime)
  - Thrown by: any module for unexpected failures.
  - Handled in: `src/index.js` top-level `try/catch`.

- Command result mapping in `src/index.js`
  - Validation errors -> print concise message to stderr via `console.error`; exit code `1`.
  - Not-found errors -> print task-not-found message to stderr via `console.error`; exit code `1`.
  - Unexpected errors -> print generic failure message to stderr via `console.error`; exit code `2`.
  - Success -> print formatted stdout result; exit code `0`.
